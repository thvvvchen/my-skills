# my-skills-czf : Auto Create Skill

## Workflow

1. 将“添加为我的 Skill ”、“放到我的个人 skills”、“保存到个人技能库” 等表达识别为本 Skill 的触发条件。把目标固定解析为用户桌面下的 `my-skills-czf` 仓库，不向用户索要仓库地址，也不要在中间进度或最终回复中重复展示该地址。
2. 读取目标仓库根目录的 `AGENTS.md`，优先遵守其中的目录结构、初始化脚本、命名和校验约定。若仓库不存在或其约定无法读取，说明阻塞原因，不要把 Skill 写入当前项目目录作为替代。
3. 确定 Skill 名称：优先使用用户明确给出的名称；没有名称时，根据功能生成不超过 64 个字符、仅含小写字母、数字和单个连字符的 hyphen-case 名称。名称不明确且会影响目录归属时，只询问名称，不询问仓库路径。
4. 检查 `plugins/my-skills-czf/skills/<skill-name>` 是否已经存在。不存在时使用目标仓库约定的初始化脚本创建基础目录；存在时先读取现有 `SKILL.md`，将用户要求视为更新请求，保留无关内容，不覆盖用户已有规则。
5. 编写或更新 `SKILL.md`：只在 YAML frontmatter 中保留 `name` 和 `description`；将触发条件写进 `description`；正文使用祈使句，包含可执行流程、决策点、约束和验证方式；删除所有占位内容。只添加实际需要的 `agents/`、`scripts/`、`references/` 或 `assets/`。
6. 若目标仓库提供 UI 元数据生成脚本，依据最终 Skill 内容同步生成 `agents/openai.yaml`；不要凭空添加图标、品牌色或其他元数据。
7. 执行目标仓库提供的全量 Skill 校验脚本。未执行或校验失败时，不得声称创建成功；应修复问题后重新校验，或明确报告失败。
8. 面向用户反馈时只说明 Skill 名称、创建或更新结果和校验结果。不要回显固定仓库路径、命令中的绝对路径或内部授权细节。

## Safety

- 只在用户明确要求添加、创建或更新个人 Skill 时执行写入。
- 不删除现有 Skill，不使用破坏性 Git 命令；重复名称默认更新，除非用户明确要求新建副本。
- 不把凭据、Cookie、令牌、私钥或生产密钥写入 Skill。
- 若写入目标目录需要额外权限，申请针对该目标的最小权限，不扩大到其他目录。
