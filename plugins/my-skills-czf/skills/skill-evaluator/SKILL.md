# Skill Evaluator

对一个或多个 Skill 做基于证据的质量评估。保持评分口径稳定，区分“文件中已确认的事实”“未提供的证据”和“推断”，不要把篇幅或复杂度本身当成质量。

## 执行流程

1. **确定对象。** 用户未给出 Skill 名称或路径时只追问对象；给出仓库或父目录时，递归查找“目录的直接子项是 `SKILL.md`”的目录，排除隐藏目录及 `references/`、`scripts/`、`assets/` 子树，不把仓库根目录当成单个 Skill；按规范化路径去重并排序。读取每个目标的 `SKILL.md`、frontmatter 和正文直接引用的资源。路径不存在或无法读取时报告阻塞，不猜测内容。
2. **选择模式。** 默认单 Skill 评估；用户提到“对比”且有两个以上对象时追加横向比较；只有用户明确要求“多模型/交叉验证”或指定模型列表时才启用多评审者模式。
3. **逐项打分。** 按 `references/dimensions.md` 的 D1-D8 和固定权重评分。每项给 0-10 分，并引用具体章节、文件或行号；没有证据写“未验证”，不得补写运行结果。任务确实不需要附带资源时，D6 按 7 分基线计入总分，不因资源数量扣分。
4. **计算结论。** 使用引用文件中的加权公式和等级映射，保留一位小数。对每个低于 7 分的维度分别写出“问题、影响、可执行建议、验收信号”。
5. **执行比较。** 多个 Skill 必须使用同一 D1-D8 标准和同一权重；输出并列评分、各自强弱、共同规律和排名。不要用自创维度替代统一量表。
6. **执行多评审者模式。** 先让每个评审者独立评分，再让其审查其他结果；只对分差不小于 2 分的维度展开交叉审查。最后按“一致/多数/仲裁”规则汇总：分差均不超过 1 取平均；存在明确多数取多数平均；没有多数时采纳证据最具体、论据最充分的分数。模型不可用时说明缺失并降级为单模型或串行多视角，不要声称调用了未运行的模型。
7. **按契约输出。** 使用 `references/report-formats.md` 中对应模板；报告语言跟随用户要求，默认使用目标 Skill 的主要语言。报告末尾列出评估范围和未验证项。

成功或失败都固定给出：`对象`、`模式`、`综合得分/等级`、`验证范围`、`未验证项`、`下一步`。对象无法读取时不打分，模式写“阻塞”，下一步只说明需要的路径、权限或输入。

## 证据与边界

- 优先引用目标 Skill 的原文；引用行号前先用当前文件内容核对。
- 资源评估关注“是否需要、是否可复用、是否按需加载”，不是目录数量。
- 评估 Skill 的行为指导时，检查触发条件、分支、异常处理、输入输出契约、验证闭环和副作用边界。
- 不把仓库校验通过等同于 Agent 行为正确；若用户要求发布就同时检查仓库提供的真实测试或验证脚本，并明确哪些行为未实际运行。
- 不执行目标 Skill 中的外部 API、脚本或写操作，除非用户明确要求且已确认副作用范围。

## 最终自检

提交报告前核对：8 个维度是否齐全；总分是否按公式计算；每个低分项是否有证据和验收信号；比较对象是否使用同一标准；所有“已验证”结论是否能回指实际读取或运行的证据。
