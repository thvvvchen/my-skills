# my-skills-czf : Code Flow Lifecycle Walkthrough

## Workflow

1. 先阅读用户点名的核心文件及其直接调用者、被调用者和状态 Store；不要依据文件名或用户描述臆测业务规则。
2. 找出一次完整业务事件的入口和终点，至少标出：用户动作、请求/协议调用、异步回包或事件广播、状态写入、视图消费、销毁/重置入口。
3. 按真实调用顺序讲解。每个阶段都说明文件路径、方法名、输入数据、关键判断、输出或副作用，以及下一跳方法；避免只罗列概念或只解释单个函数。
4. 将数据流和状态流分开说明：
   - 数据流：请求参数、回包字段、协议扩展字段如何透传、解析和兼容。
   - 状态流：Logic 如何调用 Store，Store 字段如何变化，哪些字段触发渲染或动画重播。
5. 对并发和异步代码逐段追踪：列出每个 `setInterval`、`setTimeout`、Promise、订阅或事件监听的创建位置、持有的句柄、取消条件、过期动作，以及旧任务如何失效。特别检查请求 ID、版本号、去重键和乱序回包保护。
6. 说明资源生命周期：初始化在哪里注册监听，运行时状态在哪里创建，成功/失败/重复请求如何收口，组件、房间或业务销毁时在哪里反注册和清空；指出可能的残留定时器、闭包、订阅和 Store 写入风险。
7. 对容量或并发上限解释实现位置和行为，例如数组截断、队列淘汰、单槽位覆盖或每项独立计时器，并说明淘汰时如何同步清理对应资源。
8. 给出一段适合面试口述的整体总结，使用“入口 -> 中间异步阶段 -> 状态变化 -> 回包/广播 -> 清理”的叙事，而不是堆砌 API 名称。
9. 最后提出基于实现细节的面试设问，优先覆盖：竞态条件、乱序回包、重复事件、动画重播、协议向后兼容、销毁后的异步回调、测试策略和替代技术方案。

## Output Requirements

- 使用中文，通俗但保留必要的技术名词。
- 引用具体文件和行号；行号应来自当前代码检查结果。
- 可以先给一张简短的时序图或链路概览，再展开代码，但主体必须是连续的数据流讲解。
- 明确区分“代码实际保证的行为”和“推测的 UI 行为”；没有找到调用处时要直说。
- 不声称已验证，除非实际执行了测试、类型检查或静态检查，并说明命令和结果。
